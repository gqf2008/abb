# 假绿清单：那些「看着通过了、其实没检查」的形态

> 建立于 2026-11-02。起源是一天之内在同一类问题上栽了五次：**检查看起来在跑，
> 实际没检查到东西**。每一次的表象都是**全绿**。
>
> 这份清单不是忏悔录，是**判据手册**：下次写测试/守卫/验证脚本时，逐条对照。

## 为什么单独成文

散落在提交信息里的教训只能被当次提交的人看到。而这类错误的共同特征是
**它们不留下任何异常痕迹**——测试绿、门禁绿、日志干净。所以它们会被反复重犯，
每次都以为"这次测过了"。

## 五种形态（每条都有实测案例）

### 1. 尺子量错了对象

**案例**：`glyph_ink_probe` 用 `is_dark`（`R+G+B < 300`）判墨迹，
用来量彩色 emoji（📤 浅棕、📋 浅米，普遍 450+）⇒ 永远返回 0。

**判据**：先确认测量工具对被测对象**有区分力**。加一个「已知能过」的对照样本，
对照也失败就说明尺子坏了，不是被测对象坏了。

### 2. 验证手段本身没验证

**案例**：用 `timeout 25 cargo test …` 测「超时保护是否生效」。macOS **没有 `timeout`**，
rc=127，被 `$?` 读成 0 ⇒ 看起来通过。
另一例：`gate | tail -3 && git merge` —— pipeline 退出码取 `tail` 的 0，
门禁的红被吞掉，照常合并。

**判据**：
- 闸门必须捕获退出码（`out=$(...); rc=$?`），**不能接管道**
- 用外部命令前先确认它存在（`command -v`）
- 工具本身的行为要先测一遍

### 3. 断言看结果数据，而数据恒等

**案例**：「两条重复通知只该 read 一次」断言消息条数 == 3。但假 server 读后清空，
第二次 read 返回空 ⇒ 总数恒为 3 ⇒ **删掉去重逻辑测试也不红**。

**判据**：找**不随被测行为变化而恒等**的观测量。次数 > 结果，调用 > 产物，
状态迁移 > 终态快照。

### 4. 守卫覆盖面没跟上代码增长

**案例**：`check_script_modes.sh` 只扫 `gates.sh` / `ci.toml` 的裸路径调用（7 个），
新增的 `tools/channel-mcp-dir/*.sh` 不在数据源里 ⇒ 8 个文件是 100644 而门禁绿。
它们在**干净检出会 Permission denied**，但本地文件系统权限还在，怎么跑都绿。

**判据**：守卫的**数据源**会随仓库演化失效。要么定期用全局扫描兜底
（`git ls-files -s | awk '$1=="100644"'`），要么让判据基于「仓库自身约定」
（如同目录是否已有可执行兄弟）而不是硬编码清单。

### 5. 变异没打上 ≠ 守卫失效

**案例**：给「契约行必须在第一行」补样本后做变异，jq 里替换语法没生效，
结果 `pass=131 fail=0`——看起来像"守卫抓不住"。实际是变异根本没改到代码。

**判据**：`assert r != s` 不够（字符串替换可能"成功"但语义没变）。
要看**替换后的内容**确实不同，且最好是**语义相反**的变异
（`.[0]` → `.[-1]` 而不是换个写法）。

## 一个跨条的元判据

> **把被测行为改坏，测试必须变红。**

不红的断言等于不存在。这条听起来是常识，但上面五条全都是它被违反的具体方式。

配套做法：
- 每条守卫**都要**做一次变异验证（本仓 `tools/review-cadence/mutation-selftest.sh` 是范例）
- 变异要**双向**：改坏必须红，改回必须绿
- 变异后要**确认变异真的生效**（grep 替换标记 / 看编译是否重跑）
