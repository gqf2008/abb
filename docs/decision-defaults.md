### 口径的适用边界（写清楚，避免被套用过头）

- **D1**：分享图不含思考过程。**但**会话重开时思考块在界面上是可见的（折叠态）——
  两件事不矛盾：界面是用户自己在看，分享是往外发。
- **D3**：`conf=0.64`，Jev 自己也不确定（`lower` 还有 0.22）。所以它是**可调参数**，
  不是死判据；实测某次真的因为 20000 截断了值得看的会话，就该按 T1 重问。
- **D5**：只约束「现在别删」。将来真要删（比如加了另一条可用入口），重问 T1。
  `conf=0.23` 的那两条（保留+提示词对齐 / 保留+子命令）基本持平，所以不能当「不删」的强证据——
  真正的理由是删掉那档的 `noul=0.85`。
- **D6**：`restart` 只能管「已写入的配置生效」，**不能写配置**（所以不新增授权面）；
  对「服务没在跑」它必须拒——`svc_restart` 是停+起不看状态，会绕过 owner 的停止意图。
- **D2**：只约束「本卡交付范围」，不约束「HTML 该不该做」——那是后续卡的事。

## 判据：`decisions` 字段怎么查

`patch` 条目 body 可选带 `decisions`：

```json
"decisions": {
  "asked":        [{"rid": "gen-dec-…", "q": "…", "choice": "…", "p": 0.93, "conf": 0.89}],
  "self_decided": [{"what": "…", "why": "…"}]
}
```

门禁 `tools/check_review_cadence.sh` 判三条（全部确定性，不需要读懂内容）：

| 判据 | 查什么 | 红的意思 |
|---|---|---|
| **(A1) 字段形状** | 有 `decisions` 时，`asked` 必须是数组、每条 `rid` 匹配 `^gen-dec-[0-9]+-[A-Za-z0-9]+$` | `rid` 编不出来 ⇒ 说明在假装问过 |
| **(A2) 自决项不得越界** | `self_decided[].what` / `.why` 命中 T1–T4 的关键词（`默认值`/`阈值`/`上限`/`界面文案`/`UI 文案`/`用户文案`/`用户看到`/`产品决定`/`按惯例`）| 这类本该问，却被记成自决 |
| **(A3) `conf` 与转述一致** | `asked[].conf < 0.6` 时，`q` 或调用方记录里必须出现「不确定」字样 | 低置信被包装成强结论 |

**不判**「`asked` 为空」——纯技术活真的可以不问。但字段在，人一眼能看出比例。

## 本机制的已知局限（不装成解决了）

1. **漏问仍可能**：一个决定既不碰 T1–T5、我也不写信号词、又不是二选一，机器查不出来。
2. **关键词判据可被绕过**：`self_decided` 里换个说法就不命中（但那就是刻意规避了，
   与「忘了问」是不同性质的问题）。
3. **历史 `patch` 无此字段**：判据只对新卡生效（与 `NO_REVIEW_TS` 同口径），
   不追溯判红。
4. **A1 只能防「随手写个字符串」，防不了「照格式编一个」**——这条是**实测**出来的，
   不是推测（2026-11-02，卡 `abb-cadence-t2-wordlist-20261102`）：
   我用了 `jev__jev_choice`，**它不返回 `request_id`**（只有 `jev__jev_ask` 返回），
   于是照着格式拼了一个 `gen-dec-1793633540-tHIEFs2eUvOnyueP0HdS`——**格式完全合法，
   A1 抓不到**。Jev 也没有「按 rid 查证」的接口，所以格式之外的验真只能靠**账本自曝**
   （那条 thread 里已如实登记）。
   ⇒ 硬规矩：**记档一律走 `jev__jev_ask`（可一次问多个问题，还能省 token）**；
   `jev_choice` / `jev_score` / `jev_noul` 适合即问即用、不留档的场景。
5. **A2 的词表会对「讨论词表本身」的句子误红**——实测过一次（同上卡）：
   写「补全导出范围/分享内容/提示措辞」当自决项，被这三个词判成越界。
   已按 Jev `keep_narrow_only`（p=0.98/conf=0.96）只收窄不补全；
   代价是改「导出范围 / 分享内容」目前抓不到。
